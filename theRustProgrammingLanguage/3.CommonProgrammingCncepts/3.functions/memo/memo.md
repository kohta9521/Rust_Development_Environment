# 関数

関数は、Rust のコードにおいてよく見かける存在です。
既に、言語において最も重要な関数のうちの 1 つを目撃していますね。そう、**main**関数です。
これは多くのプログラムのエントリーポイントになります。**fn** キーワードも既に見かけましたね。これによって新しい関数を宣言することができます。

Rust の関数と変数の命名規則は、**スネークケース** を使うのが慣例です。スネークケースとは、全文字を小文字にし、単語区切りにアンダースコアを使うことです。以下のプログラムでサンプルの関数定義をご覧ください。

```rust
fn main() {
    println!("Hello, world!");
}

fn another_function() {
    println!("Another function."); // 別の関数
}
```

Rust において関数定義は、fn キーワードで始まり、関数名の後に丸括弧の組みが続きます。波括弧がコンパイラに関数本体の開始と終了の位置を伝えます。

定義した関数は、名前に丸括弧の組みを続けることで呼び出すことができます。another_function 関数がプログラム内で定義されているので、main 関数ないから呼び出すことができるわけです。ソースコード中で another_function を main 関数の後に定義していることに注目してください
もちろん main 関数に定義することもできます。コンパイラは、関数がどこで定義されているかは気にしません。どこかで定義されていることのみ気にします。

functions という名前の新しいバイナリ生成プロジェクトを始めて、関数についてさらに深く探究していきましょう。another_function の例を src/main.rs ファイルに配置して走らせましょう。
以下のような出力が得られるまずです

```bash
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished dev [unoptimized + debuginfo] target(s) in 0.28s
     Running `target/debug/functions`
Hello, world!
Another function.
```

行出力は、main 関数内に書かれた順序で実行されています。最初に"Hello, world"メッセージが出て、それから another_function が呼ばれて、こちらのメッセージが出力されています。

## 関数の引数

関数は、引数を持つようにも定義できます。引数とは、関数シグニチャの一部になる特別な変数のことです。関数に引数があると、引数の位置に実際の値を与えることができます。
技術的にはこの実際の値は**実引数**と呼ばれますが、普段の会話では、仮引数（parameter）と実引数（argument）を関数定義の変数と関数呼び出し時に渡す実際の値、両方の意味に区別なく使います。
どちらも単に引数と呼ぶことが多いでしょう。

以下の書き直した another_function では、Rust の仮引数がどのようなものかを示しています。

```rust
fn main() {
    another_function(5);
}

fn another_function(x: i32) {
    println!("The value of x is: {}", x);   // xの値は{}です
}
```

another_function の宣言には、x という名前の仮引数があります。
x の型は、i32 と指定されています。値５が another_function に渡されると、println!マクロにより、フォーマット文字列中の人組の波括弧があった位置に値５が出力されます。

関数シグニチャにおいて、各仮引数の型を宣言しなければなりません。
これは、Rust の設計において、意図的な判断です。関数定義で型注釈が必要不可欠ということは、コンパイラがその意図するところを推し量るのに、プログラマがコードの他の箇所で使用する必要がないということを意味します。

関数に複数の仮引数を持たせたいときは、仮引数定義をカンマで区切ってください。こんな感じです。

```rust
fn main() {
    print_labeled_measurement(5, 'j');
}


fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("The measurement is: {}{}", value, unit_label);
}
```

### 関数本体は、文字と式を含む

関数本体は、文が並び、最後に式を置くか文を置くという形で形成されます。現在までには、四季で終わらない関数だけを見てきたわけですが、式が文の一部になっているものなら見かけましたね。
Rust は、式指向言語なので、これは理解しておくべき重要な差異になります。他の言語にこの差異はありませんので、文と式が何あのかと、その違いが関数本体にどんな影響を与えるかを見ていきましょう。

実のところ、もう文と式は使っています。文とは、何らかの動作をして値を返さない命令です。式は結果値に評価されます。ちょっと例を眺めてみる

**let**キーワードを使用して変数を生成し、値を代入することは文になります。

```rust
fn main() {
    let y = 6;
}
```

関数定義も文になります。つまり、`fn main() { ... }` という関数定義全体も文として扱われます。

**文は値を返しません**。これが重要なポイントです。つまり、`let`文を使って変数を作成する行為自体は、何も結果を返さない「行動」なのです。

##### 例え話：文と式の違い

- **文（Statement）**：何かをする「行動」で、結果を返さない
  - 例：「本を読む」という行動は、何かをするが、結果として何かを返すわけではない
- **式（Expression）**：何かを計算して「結果」を返す
  - 例：「5 + 3」という計算は、結果として「8」を返す

`let y = 6;` は「変数 y に 6 を代入する」という行動（文）なので、結果を返しません。そのため、`let`文を他の変数に代入することはできません。

以下のコードは、`let y = 6;` という文を `x` に代入しようとしていますが、文は値を返さないため、エラーになります：

```rust
fn main() {
    let x = (let y = 6);  // エラー！文は値を返さないので代入できない
}
```

もし値を返したい場合は、式を使う必要があります。例えば：

```rust
fn main() {
    let x = 6;           // これはOK：6という式の結果をxに代入
    let y = (5 + 1);     // これもOK：(5 + 1)という式の結果をyに代入
    // let z = (let w = 6);  // これはエラー：let文は値を返さない
}
```

**まとめ**：

- `let y = 6;` は文（行動）なので、値を返さない
- 文を変数に代入することはできない
- 値を返したい場合は、式（計算やリテラル値）を使う必要がある

この let y = 6 という文は値を返さないので、x に束縛するものがないわけです。
これは C や Rubyn アドの言語とは全く異なる動作です。C や Ruby では、代入は代入値を返します。これらの言語では、x = y = 6 とかいて、x も y も値６になるようにできるのですが、Rust においては、そうは問屋が下さないわけです。

式は何かに評価され、これからあなたが書く Rust コードの多くを構成します。簡単な数学演算を思い浮かべましょう。この例は、値 11 に評価される式です。式は文の一部になり得ます。

### ブロック式：中括弧 `{}` は式になる

ここで重要な概念を理解しましょう。Rust では、**中括弧 `{}` で囲まれたブロックも式になります**。これが混乱しやすいポイントです。

以下のコードを見てみましょう：

```rust
fn main() {
    let y = {
        let x = 3;
        x + 1
    };

    println!("The value of y is: {}", y);
}
```

##### なぜこれが動作するのか？

**重要なポイント**：

1. **ブロック `{ ... }` 自体は式**です
2. **ブロック内の最後の行**が、ブロック全体の値を決定します

   - セミコロン**なし** → 式として扱われ、値が返される
   - セミコロン**あり** → 文として扱われ、値は返されない（`()` になる）

3. **`};` のセミコロンは `let y = ...` という文を終わらせるためのもの**です。これはブロックの中身とは関係ありません。

##### 詳しく見てみましょう

```rust
let y = {           // ← ここからブロック式が始まる
    let x = 3;      // ← これは文（セミコロンあり）。値を返さない
    x + 1           // ← これは式（セミコロンなし）。値4を返す
};                  // ← このセミコロンは「let y = ...」という文を終わらせる
```

**動作の流れ**：

1. `let x = 3;` が実行される（文なので値を返さない）
2. `x + 1` が評価される（式なので値 `4` を返す）
3. ブロック全体が値 `4` になる
4. `let y = 4;` という文が実行される

##### 例え話：ブロック式を理解する

ブロック式は、**「作業をして、最後に結果を出す」**という箱のようなものです。

- 箱の中（ブロック内）で作業をします（`let x = 3;` という文）
- 箱の最後に結果を置きます（`x + 1` という式）
- 箱全体がその結果の値になります

##### セミコロンの有無で何が変わる？

```rust
// パターン1：最後にセミコロンなし → ブロックが値を返す
let y = {
    let x = 3;
    x + 1        // ← セミコロンなし：式。値4を返す
};              // y = 4

// パターン2：最後にセミコロンあり → ブロックが値を返さない
let y = {
    let x = 3;
    x + 1;      // ← セミコロンあり：文。値を返さない
};              // y = () （ユニット型、空の値）

// パターン3：ブロック内に文だけ → 値を返さない
let y = {
    let x = 3;
    let z = 4;  // ← 文だけなので、ブロック全体は () を返す
};              // y = ()
```

##### なぜ `let y = { ... };` のセミコロンが必要なのか？

`};` のセミコロンは、**`let y = ...` という文を終わらせるため**です。

- `let y = { ... }` までだと、文が終わっていない
- `let y = { ... };` で、文が完成する

これは、以下のような通常の文と同じです：

```rust
let x = 5;      // ← セミコロンで文を終わらせる
let y = { ... }; // ← セミコロンで文を終わらせる（ブロックの中身とは別）
```

##### まとめ

- **ブロック `{}` は式**で、値を返すことができる
- **ブロック内の最後の行**が、ブロック全体の値を決定する
  - セミコロンなし → 式として値が返される
  - セミコロンあり → 文として `()` が返される
- **`};` のセミコロン**は、`let` 文を終わらせるためのもので、ブロックの中身とは関係ない
- ブロック内に文と式を混在させることができる

## 戻り値のある関数

関数は、それを呼び出したコードに値を消すことができます。
戻り値に名前をつけはしませんが、矢印のあとに型を書いて確かに宣言します。Rust では、関数の戻り値は、関数本体ブロックの最後の式の値と同義です。return キーワードで関数から早期リターンし、値を指定することもできますが、多くの関数は最後の式に暗黙的に返します。こちらが値を返す関数の例です。

```rust
fn five() -> i32 {
    5
}

fn main() {
    let x = five();
    println!("The value of x is: {}", x);
}
```
