## 複合型

複合型により、複数の値を 1 つの型にまとめることができます。Rust には、２種類の基本的な複合型があります。タプルと配列です。

### タプル型

タプルは、複数の型の何らかの値を 1 つの複合型にまとめ上げる一般的な手段です。
タプルは、丸括弧の中にカンマ区切りの値リストを書くことで生成します。タプルの位置ごとに型があり、タプルの内の値はそれぞれ全てが同じ型である必要はありません。今回の例では、型注釈をあえて
追加しました。

```rust
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
}
```

変数 tup は、タプル全体に束縛されています。なぜならタプルは、1 つの複合要素と考えられるからです。
タプルからここの値を取り出すには、パターンマッチングを使用して分解することができます。以下のように

```rust
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
    let (x, y, z) = tup;
    println!("The value of x is: {}", x);
    println!("The value of y is: {}", y);
    println!("The value of z is: {}", z);
}
```

このプログラムは、まずタプルを生成し、それを変数 tup に束縛しています。
それから let とパターンを使って tup 変数の中身を 3 つの個別の変数(x, y, z)に変換しています。この過程は、分配と呼ばれいています。
単独のタプルを破壊して３分割しているからです。最後に、プログラムは y 変数の値を出力します。

```rust
fn main() {
    let x: (i32, f64, u8) = (500, 6.4, 1);
    let five_hundred = x.0;
    let six_point_four = x.1;
    let one = x.2;
}
```

このプログラムは、新しいタプル x を作成し、添え字アクセスで各要素に対して新しい変数も作成している。
多くのプログラム言語同様、タプルの最初の添えずは０です。

### 配列型

配列によっても、複数の値のコレクションを得ることができます。
タプルと異なり、配列の全要素は、同じ型でなければなりません。Rust の配列は、他の言語と異なっています。Rust の配列は、固定長です。一度宣言されたら、サイズを伸ばすことも縮めることもできません。

Rust では、配列に入れる要素は、各括弧内にカンマ区切りリストとして記述します。

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];
}
```

配列は、ヒープよりもスタックにデータのメモリを確保したいとき、または、常に固定長の要素があることを確認したい時に有効です。
ただ、配列はベクタ型ほど柔軟ではありません。ベクタは、標準ライブラリによって提供されている配列と似たようなコレクション型で、こちらは
サイズを伸縮させることができます。配列とベク型、どちらを使うべきか確信が持てない時は、おそらくベクタ型を使うべきです。第 8 章でベクタについて詳細に議論します。

#### ヒープとスタックとは？

プログラムが実行される際、データを保存するためのメモリ領域には主に 2 つの種類があります：**スタック**と**ヒープ**です。

##### スタック（Stack）

スタックは、**本を積み重ねるように**データを保存するメモリ領域です。

- **特徴**：

  - 非常に高速にアクセスできる
  - サイズが固定されている（コンパイル時に決まる）
  - データの追加・削除は「上から」しかできない（LIFO: Last In First Out）
  - 関数が終了すると自動的に解放される

- **例え話**：
  レストランの食器洗い機のトレイを想像してください。洗った食器を上から積み重ね、使うときは上から取ります。これがスタックです。

- **Rust での例**：

```rust
fn main() {
    let x = 5;        // スタックに保存される
    let arr = [1, 2, 3];  // 配列もスタックに保存される（固定サイズだから）
}
```

##### ヒープ（Heap）

ヒープは、**自由に使える広い土地**のようなメモリ領域です。

- **特徴**：

  - サイズが可変（実行時に決まる）
  - スタックよりアクセスが遅い
  - 明示的に管理する必要がある（Rust では自動的に管理される）
  - 大きなデータやサイズが分からないデータに適している

- **例え話**：
  大きな倉庫を想像してください。必要な分だけ借りて、使わなくなったら返します。どこに何を置いたかは「住所（ポインタ）」で管理します。

- **Rust での例**：

```rust
fn main() {
    let vec = Vec::new();  // ベクターはヒープに保存される（サイズが可変だから）
    vec.push(1);
    vec.push(2);  // 後から要素を追加できる
}
```

##### スタックとヒープの違いまとめ

| 特徴   | スタック                   | ヒープ                           |
| ------ | -------------------------- | -------------------------------- |
| 速度   | 非常に速い                 | やや遅い                         |
| サイズ | 固定（コンパイル時に決定） | 可変（実行時に決定）             |
| 管理   | 自動（関数終了時に解放）   | 自動（Rust の所有権システム）    |
| 用途   | 小さな固定サイズのデータ   | 大きなデータや可変サイズのデータ |

##### なぜ配列はスタックに保存されるのか？

配列は固定サイズなので、コンパイル時に必要なメモリ量が分かります。そのため、高速なスタックに保存するのが効率的です。

一方、`Vec`（ベクター）のような可変長のコレクションは、実行時にサイズが変わる可能性があるため、ヒープに保存されます。

```rust
fn main() {
    // スタックに保存される（固定サイズ）
    let arr = [1, 2, 3, 4, 5];

    // ヒープに保存される（可変サイズ）
    let mut vec = vec![1, 2, 3];
    vec.push(4);  // 後から要素を追加できる
}
```

### 配列の要素にアクセスする

配列は、スタック上に確保される一塊のメモリです。添字によって、配列の要素にこのようにアクセスをすることができます。

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];

    let first = a[0];
    let second = a[1];
}
```

この例では、first という名前の変数には 1 という値が格納されます。
配列の[0]番目にある値が、それだからです。second という名前の変数には、配列の[1]番目の値２が格納されます。

### 配列要素への無効なアクセス

配列の終端を超えて要素にアクセスしようとしたら、どうなるでしょうか？
先ほどの例を以下のように変えたとすると、コンパイルは通りますが、実行するとエラーで修正します。

```rust
use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("配列の何番目の要素にアクセスするか指定してください");

    let mut index = String::new();

        io::stdin()
        .read_line(&mut index)
        .expect("Failed to read line");
              // 値の読み込みに失敗しました

    let index: usize = index
        .trim()
        .parse()
        .expect("Index entered was not a number");
        　　　// 入力された値は数字ではありません

    let element = a[index];

    println!(
        "The value of the element at index {} is: {}",
        // {}番目の要素の値は{}です
        index, element
    );
}
```
